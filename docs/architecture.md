# 架构说明与开发路线

## 当前设计

1. GitHub Issue（标题 `[DeepSeek]`）或拥有者评论触发 `deepseek-relay.yml`。
2. 工作流读取仓库 Secret `DEEPSEEK_API_KEY`，执行 Python 标准库编写的 `scripts/relay.py`。
3. 程序通过官方 Chat Completions API 请求 `deepseek-flash`，限制输出 token 数和单次运行时长。
4. 响应写入对应 Issue 的机器人评论，作为可读的审核记录。
5. 经过审查的示例 bpy 代码存放于 `scenes/house_v1.py`，可单独由 `render-house.yml` 执行。
6. 后台 Blender 4.x 加载脚本，保存 `.blend` 与 `.png` 到临时输出目录。
7. GitHub Actions Artifact 保存结果，供用户下载或由具有文件读取能力的工具审查。

## 已知限制

- 当前属于**异步任务**，非低延迟的实时对话 API 连接。
- 代码生成和渲染通过 GitHub 文件提交衔接，未形成任意代码全自动执行闭环。
- 图像质量由设计规范、模型输出及人工审查共同决定。
- Issue 历史仅按程序限制读取有限评论，不是长时记忆系统。
- 云端 Blender 的安装速度和渲染效率受 Actions runner 资源影响。
- 仅展示通过验证的小房子示例；尚无任意新场景的参数化通用生成器。

## 安全边界

该项目将“模型提出代码”和“实际执行代码”分离。**审查和授权步骤不是装饰**：因为生成的 Python 脚本可能包含危险的文件或网络操作，所以默认只运行提交到仓库的、由仓库维护者审核过的示例代码。
